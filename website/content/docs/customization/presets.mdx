By default, any configuration you add in your own `panda.config.js` file is smartly merged with the
[default configuration](#), allowing you to override or extend specific parts of the configuration.

You can specify a preset in your `panda.config.js` file by using the `presets` option:

```js
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  presets: ['@acmecorp/panda-preset']
})
```

## Creating a preset

Presets are also valid Panda configuration objects, taking a similar shape to the configuration you would add in your
`panda.config.ts` file.

> **Note:** Every preset must have a unique name.

```js
// my-preset.js
import { definePreset } from '@pandacss/dev'

export default definePreset({
  name: 'my-preset',
  theme: {
    tokens: {
      colors: {
        rose: {
          50: { value: '#fff1f2' },
          // ...
          800: { value: '#9f2233' }
        }
      }
    }
  }
})
```

You can then use this preset in your `panda.config.ts` file:

```js
// panda.config.ts
import { defineConfig } from '@pandacss/dev'
import myPreset from './my-preset'

export default defineConfig({
  presets: [myPreset]
})
```

The available keys for a preset are:

- [`conditions`](/docs/concepts/conditional-styles)
- [`globalCss`](/docs/concepts/writing-styles#global-styles)
- [`globalFontface`](/docs/guides/fonts#global-font-face)
- [`patterns`](/docs/concepts/patterns)
- [`staticCss`](/docs/guides/static)
- [`theme`](/docs/customization/theme)
- [`utilities`](/docs/customization/utilities)

### Asynchronous presets

There are cases where you need to perform logic to determine the content of your preset, you'd call functions to do
this. In cases where they're asynchronous; panda allows promises, given that they resolve to a valid preset object.

```js
// my-preset.js
export default async function myPreset() {
  const roseColors = await getRoseColors()

  return definePreset({
    name: 'my-preset',
    theme: {
      tokens: {
        colors: {
          rose: roseColors
        }
      }
    }
  })
}
```

You can then use this preset in your `panda.config.ts` file:

```js
// panda.config.ts
import { defineConfig } from '@pandacss/dev'
import myPreset from './my-preset'

export default defineConfig({
  presets: [myPreset()]
})
```

### Marking entries as internal

Design systems usually have three layers of tokens: **raw**, **semantic**, and **component**. The lib uses all three to build itself, but only the semantic layer should be reachable from consumer code.

The `internal` field on a preset marks paths that are usable inside the lib package but stripped from the consumer's generated types and IntelliSense:

```ts
// my-ds/preset.ts
import { definePreset } from '@pandacss/dev'

export default definePreset({
  name: '@acme/ds/preset',
  theme: {
    extend: {
      tokens: {
        colors: {
          raw: {
            gray: { 50: { value: '#f8fafc' }, 900: { value: '#0f172a' } }
          }
        }
      },
      semanticTokens: {
        colors: {
          surface: { value: '{colors.raw.gray.50}' },
          text: { value: '{colors.raw.gray.900}' }
        }
      }
    }
  },
  internal: {
    tokens: ['colors.raw.*']
  }
})
```

A consumer that references this preset via `designSystem` sees `colors.surface` and `colors.text` in autocomplete, but not `colors.raw.gray.50`. The lib itself still uses `colors.raw.gray.50` freely when defining the semantic layer.

**Scope.** `internal` accepts arrays of dot-paths for any of: `tokens`, `semanticTokens`, `recipes`, `patterns`, `conditions`, `keyframes`. Paths support a single-segment `*` wildcard (`'colors.raw.*'` matches `colors.raw.gray.50` and `colors.raw.blue.500` but not `colors.raw.gray.50.alpha`).

**When the filter runs.** Only presets reached through a consumer's `designSystem` field (and their transitive `presets:` chain) are filtered. Presets imported directly via `presets:[]` are user-controlled and never filtered — the lib author and the consumer are the same person.

**Type enforcement.** Internal paths are removed from the generated type surface (`Tokens['colors']`, `ColorPalette`, recipe/pattern/condition keys). Full TypeScript enforcement requires `strictTokens: true` on the consumer config; without it, internal names are absent from autocomplete but TypeScript still accepts arbitrary strings on style props.

## Which panda presets will be included ?

![Visual helper](/stately-presets-merging.png)

- `@pandacss/preset-base`: ALWAYS included if NOT using `eject: true`

- `@pandacss/preset-panda`: only included by default if you haven't specified the `presets` config option, otherwise
  you'll have to include that preset by yourself like so:

```ts
import pandaPreset from '@pandacss/preset-panda'
import { defineConfig } from '@pandacss/dev'

export default defineConfig({
  // ...
  presets: [pandaPreset, myCustomPreset]
})
```
